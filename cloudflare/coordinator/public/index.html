Chat, history and permission help

Work with AI

Runs Claude Code or Codex on your own computer, signed in with your own account. Smith keeps your chats and relays the conversation; your login never leaves your computer.

Pull requests

Branches proposed for merging into a project, by crew members and from chats. Review the change here and merge it, wherever the project is hosted: a build machine does the merge and pushes it, never forced.

Crew

Named AI members that look after this workspace’s projects on their own: on a schedule, after builds, or when someone presses Run now. Each works on its own branch of a project and reports back for a person to review; nothing is merged or deployed for you. A crew member runs with this machine’s Claude Code sign-in, the workspace’s Anthropic API key, or a model on the machine. Owners choose which machines run crew.

Crew activity and spending controls: stop all crew, limit concurrency and API spending, or disable expensive check-in work. Owners and admins save workspace controls; operators can pause individual members.

Runs

Check-ins select only opted-in agents. Inspect selection reasons, pinned commits, budgets, writer scopes and findings here. Dry run selection starts no work.

Proposals from every crew member, newest first. A person verifies, accepts or dismisses each one: Verify runs the branch’s build script on a build machine (without the workspace’s secrets), Accept marks it for you to merge from its branch, and a dismissal’s note becomes feedback in the member’s memory.

Messages between crew members, and from people to them, newest first. A member reads the ones to it or to everyone at the start of its next run, as information it may weigh, never as orders.

Smith tokens — help

A Smith token connects an external assistant to this workspace's build API. It is separate from your provider login, agent enrollment and Cloudflare credentials. Copy it once, use a descriptive name per tool and revoke it when no longer needed. Token setup and scope

Tokens for Claude Code, Codex and git

Give your own coding agent a Smith token so it can see projects and machines, start builds and read their logs as you. It cannot deploy, change members or read your chats. The same token is the password for cloning Smith’s copies of your repositories (Clone on a project card); one that can start builds can push to them.

Cloudflare 

          
Lets build scripts on your machines publish to Cloudflare (Wrangler, Pages, DNS). The token is stored write-only and reaches jobs only as CLOUDFLARE_API_TOKEN when a machine claims a build. Every build in this workspace can read it. If this account has Cloudflare Artifacts, adding Artifacts Edit to the token lets Smith keep its project copies here.

          

          
Create a scoped token (for example Workers Scripts:Edit or Pages:Edit). Leave blank to keep the current token.

          

          
GitHub 

          
Optional. Smith normally reads smith.json through the GitHub account you linked at the top of the page, and lists your repositories from it. Only if nobody in this workspace can link GitHub, store a fine-grained token here with read-only Contents and Metadata access. It is stored write-only and never given to builds or coding agents.
